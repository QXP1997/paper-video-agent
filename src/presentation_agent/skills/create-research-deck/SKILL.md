# 生成研究演示文稿

将 `deck_spec.json` 视为唯一事实来源。不要让 PPTX 或视频成为唯一可用产物；下游渲染器必须能从该规格重建演示文稿。

## 组织演示文稿

1. 检查用户提供的材料，确定受众、格式和演示目标。不得虚构结论、数字、引语或来源位置。
2. 起草幻灯片前先建立证据清单。把每篇论文、网页、笔记或数据集登记到 `sources`，并为事实声明和源材料资产附上引用。
3. 设计一条连贯的叙事主线。每页只承担一个明确的传达目的，标题使用易懂语言，并提供可用于后续解说的演讲备注。
4. 优先用视觉方式解释，避免堆叠密集正文。原始图表清晰且授权允许时优先复用；数据图表可使用 Matplotlib 或 Jupyter，动态概念可使用 Manim，生成式图像仅用于非事实性的概念说明。
5. 把每个外部或生成的视觉素材登记到 `assets`。已落盘的素材使用 `path`；尚未生成的素材必须给出足够具体的 `prompt` 和预期生成器。
6. 在 `build_steps` 中表达渐显、高亮、聚焦和播放意图。它们是与渲染器无关的指令，不代表某种 PPT 动画已经完成。
7. 将结果写入任务契约指定的输出路径，然后运行：

   ```text
   python -m research_presentation_core validate <deck_spec.json>
   ```

8. 修复所有校验错误。如果环境提供渲染器且用户要求渲染，应渲染全部页面，逐页检查裁切、溢出、对比度、视觉层级和证据位置，再进行修订。

## 内容与视觉约束

- 封面保持简洁，不在标题页堆放高密度摘要。
- 整套演示文稿使用统一的视觉系统，但页面构图应根据内容变化。
- 避免泛化的 AI 装饰、过多卡片、纯装饰渐变和未解释图标。
- 渲染器支持时，图表、表格、公式和图示应尽量保持可编辑。
- 引用必须解析到已声明的 `source_id`。详细来源信息放在演讲备注或引用中，不要挤占主视觉区域。
- 如果素材只有生成提示词，不得将其表述为已完成的图像。
- 规格必须保持渲染器中立，使同一份规格可用于 PPTX、网页幻灯片和解说视频。

## 完成标准

只有当 SlideDeckSpec 通过确定性校验、所有引用均可解析、每页都有可用的演讲备注，且用户要求的输出文件实际存在时，任务才算完成。如果用户要求渲染，还必须完成所有渲染页面的视觉检查。
