# 第八批：评测入口与验收记录

2026-09-16。**评测基础已完成，真实任务正在执行；规划稳定性和生产 Profile 尚未验收，批次未完成。**

## 已交付与实际结果

`evals/tasks.py` 提供 18 个版本化微型代码任务，开发/回归/保留集合各六类，包含初始文件、受保护文件、在线与独立终态断言。`strategies.py` 提供受约束 ReAct、固定 Todo、失败反馈后的全局重分解，以及原三层流程的八组策略组合。`run.py` / `report.py` 实现配置与代码指纹、固定 seed 调度、隔离工作区、逐次持久结果、独立验收和指标汇总。

全部复用原 ModelBackend、RunService、Planner、Actor、ToolExecutor、验证器、SQLite 和 Dulwich。没有新增生产 Backend、数据库迁移或第二套工具执行通道。准确的对照含义、命令与计量边界见 [evals/README.md](../evals/README.md)。

全量 **201 项测试通过，本批新增 14 项**。覆盖五种主要调度装配、十八个任务的缺陷/正确修复/受保护文件、暂停和追加约束、实际全局重分解、计划覆盖修正、无覆盖时不调用 Actor、环境阻塞和误完成计量。评分回归还构造了提前 `SystemExit(0)` 的实现：普通 COMMAND 检查可能通过，但独立评分因缺少最终标记判为失败。这些脚本模型结果验证评测器，不计作真实模型成功率。

使用现有 `deepseek-flash` 配置执行了真实 Todo / Stage 规划探针，发现模型会把仅有 TASK 检查的约束写入 Todo.done_when / Stage.expected_results。原有 JSON、版本及 addresses 校验不足以拦截，只有后续验证才会发现无法覆盖。现在在原 Planner 中校验初始/修订 Todo 的 TODO 层覆盖以及 Stage 的全部 STAGE 层结果；缺失时沿用原有界协议修正，并提示对应层级的可用目标。

调试探针依次出现未覆盖计划、修正耗尽、一次成功以及再次修正耗尽，全部记录保留。一次成功不代表稳定：曾有探针用了 **5 次模型尝试、14,571 Token、0 次工具执行**，Stage 仍复制 Task 专属约束，在修正次数耗尽后被拒绝。补充检查目录提示后，最新探针已通过，说明提示有帮助，但尚未形成重复试验稳定性证据。当前校验能阻止问题进入行动，模型稳定遵守计划协议仍是待解决项。

早先本机 SRT 预检曾返回 `srt-win.exe` `[WinError 5] 拒绝访问`。退出 360 后重新检查已恢复：SRT `0.0.74` 通过预检，固定 `python -I -B -c "print(123456789)"` 在沙箱退出码 0。此前的阻塞批次仍保留为历史环境记录，不能与新结果混合。修复评分端空 stdin 后，真实 `fixed_todo` 开发集 6 项完成：4 项通过，cross_module / long_running 因进入 WAITING 未通过；Explicit 在 `all` 动态策略下通过，而关闭三项策略的 `base` 仍因规划输出未满足协议进入 WAITING。这是观察结果，不是足以选择默认 Profile 的样本。

运行原始结果保存在 `.qharness/evals/`，属于本地运行数据，不提交到 Git。规划探针无 Actor 或沙箱命令，用量单列，不能算分页任务完成；不同代码迭代的探针不混合成统计成功率。

现有 [08_srt_sandbox.py](../examples/08_srt_sandbox.py) 提供准备、初始化和固定命令试运行入口；其 `sandbox.setup()` 按原实现需要用户确认及 Windows UAC。本批没有修改系统隔离或降级到宿主机执行模型代码。真实沙箱已恢复，可运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evals.run --categories explicit --variants base all --repeats 1
.\.venv\Scripts\python.exe -X utf8 -m evals.run --split dev --variants base all --repeats 3
```
